# Kara — کارا

کارا (Kara)، بستر مشترک ایجنت‌های شرکت با قالب‌های قابل استفاده برای پروژه‌ها و نقش‌های مختلف است. نام این پروژه و محصول برای معرفی به تیم‌ها و کاربران «Kara / کارا» است.

این شاخه راه‌اندازی Kara، تنظیمات محیط، رابط فارسی و راست‌به‌چپ، اتصال مدل و مدیریت پروژه‌های متعدد را نگهداری می‌کند.

بستر مشترک ایجنت‌های شرکت؛ کلاسور اولین محصول استفاده‌کننده است.

هدف نسخهٔ اول: ورود درخواست، تحلیل نیازمندی، تصمیم مالک محصول و تولید بستهٔ توسعه. توسعه‌دهنده با ابزار انتخابی خود کار را انجام می‌دهد و مرج دستی با TL است.

## شاخه‌های پروژه

- `master`: بستر اصلی Kara و تمام بررسی‌ها، نیازمندی‌ها و برنامه‌ریزی‌های فعلی.
- `agents`: ایجنت‌ها و قالب‌های مشترک؛ مبتنی بر بستر `master`.
- `clasor-agents`: پیاده‌سازی اختصاصی ایجنت‌های کلاسور؛ مرحلهٔ قرارداد PA-04 آغاز شده است. دارایی‌های اختصاصی در همین شاخه می‌مانند.

[راهنمای شاخه‌ها](docs/branches.md) روش انتخاب شاخه و همکاری را توضیح می‌دهد. شاخهٔ اصلی قبلی، `main`، اکنون `master` نام دارد.

## شروع محلی

پیش‌نیاز: Git، Python 3.12 یا جدیدتر، Docker فعال و Docker Compose 2.24.4 یا جدیدتر. روی macOS می‌توان از Colima یا Docker Desktop استفاده کرد. مراحل مخصوص این سیستم و وضعیت اجرای واقعی در [راهنمای محیط محلی](docs/local-development.md) ثبت می‌شوند.

```sh
make setup
make up
```

محیط وب محلی: <http://localhost:8080>. در اولین اجرا، راه‌اندازی حساب مدیر از مسیر <http://localhost:8080/install> انجام می‌شود. تنظیم حساب مدیر و اتصال مدل در Kara انجام می‌شود.

رابط این پروژه فارسی و راست‌به‌چپ است. اولین `make up` نسخهٔ فارسی رابط را می‌سازد و ممکن است چند دقیقه طول بکشد؛ اجرای بعدی از تصویر ساخته‌شده استفاده می‌کند. [راهنمای رابط فارسی](docs/persian-interface.md) روش نگهداری ترجمه و چیدمان را توضیح می‌دهد.

```sh
make status
make doctor
make down
```

تنظیمات اختیاری را از `.env.local.example` در `.env.local` کپی کنید. `make down` سرویس‌ها را متوقف می‌کند و داده‌های محلی را حفظ می‌کند. فرمان راه‌انداز برای حذف داده‌ها ندارد.

## ساختار پروژه

- `infra/`: نسخهٔ ثابت Dify و تنظیمات اجرای محلی.
- `scripts/`: آماده‌سازی، اجرا و بررسی محیط.
- `docs/`: راهنمای محیط، رابط و همکاری.
- `kara_contracts/`: قراردادهای قابل آزمون بستر؛ فعلاً مستقل از API اجرایی.
- `prompts/`: دستورالعمل‌های نسخه‌دار نقش‌ها.
- `workflows/`: قالب‌ها و فرایندهای قابل اشتراک.
- `fixtures/`: درخواست‌های ساختگی ارزیابی و آزمون قراردادهای عمومی Kara.
- `.runtime/`: سورس دریافت‌شدهٔ Dify، تنظیمات محرمانه و داده‌های اجرای هر نفر؛ خارج از Git.

مبنای فنی upstream پروژه، نسخهٔ مشخصی از Dify است؛ راه‌انداز همان نسخه را دریافت می‌کند و کد upstream در مخزن شرکت کپی نمی‌شود. تنظیمات مشترک در همین مخزن نگهداری می‌شوند. مجوز upstream از مخزن اصلی همراه دریافت سورس موجود است.

## همکاری سه نفره

راهنمای [همکاری و Git](CONTRIBUTING.md) مبنای کار است. هر نفر محیط و دادهٔ محلی خود را دارد. تغییرات مشترک Kara و تنظیمات اجرایی در Git ثبت می‌شوند. در این مرحله مخزن فقط محلی است؛ مالک پروژه Remote را بعداً دستی اضافه می‌کند.

کارهای مشترک شامل زیرساخت، اتصال مدل و رابط فارسی هستند. افراد می‌توانند مسئولیت‌ها را جابه‌جا کنند و تغییرات در شاخهٔ جدا بررسی می‌شوند.
