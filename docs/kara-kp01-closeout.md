تاریخ: ۲۲ اکتبر ۲۰۲۶. مبنای شروع `158f968` روی `master`. این کار فقط دو مورد باز [بازبینی KP-00 و KP-01](kara-kp00-kp01-review.md) را می‌بندد؛ KP-02 و ایجنت‌های کلاسور در این کار شروع نشده‌اند.

وضعیت: **دو مورد باز بسته شدند و KP-01 پذیرفته است.** تصویر نهایی `d31f6cb2a7f9` از Dockerfile مشترک ساخته و روی بانک اصلی اجرا شد؛ سلامت و smoke نهایی نیز موفق بودند. پذیرش مربوط به محدودهٔ KP-01 است، نه کل هستهٔ همکاری تیمی.

## نام محصول

- عنوان پیش‌فرض، نام قابل دسترس و نشان ناوبری، لوگوی ورود/راه‌اندازی و دستگاه، پنجرهٔ درباره و favicon به Kara تغییر کردند. چهار صفحهٔ اختصاصی پروژه/اعضا پسوند قدیمی و تکراری ندارند؛ برای نمونه، عنوان واقعی مرورگر «پروژه‌ها - Kara» است.
- متن‌های داخلی ورود، حساب، راهنما، دانش و گردش‌کار که به خود محصول اشاره می‌کنند یکدست شدند. نام‌های فنی، API، فایل‌های upstream، مجوز و انتساب LangGenius و ارجاع بازار/سرویس بیرونی حفظ شدند. branding اختصاصی فعال همچنان در شاخهٔ فعلی کد مقدم است؛ پذیرش Enterprise در این محیط ادعا نمی‌شود.
- تغییرات از overlay و `branding.patch` روی کپی آمادهٔ ساخت اعمال می‌شوند؛ checkout قفل‌شدهٔ upstream تغییر نکرد.

## ساخت استاندارد و دریافت وابستگی‌ها

- ساخت کامل `infra/web/Dockerfile` با کش معتبرِ مرحلهٔ وابستگی و شبکهٔ قطع موفق شد: نصب `--offline --frozen-lockfile` و `npm ci --offline`، بررسی TypeScript، ۱۴ آزمون رابط/RTL، کامپایل کامل Next.js و تولید تصویر production. `.next` قدیمی پیش از ساخت پاک شد و cache کامپایل پیش از ذخیرهٔ لایه حذف شد. استخراج یا کپی دستی خروجی کامپایل، مسیر تولید تصویر نبود.
- پس از بازیابی اینترنت، رجیستری npm پاسخ 200 داد و تلاش دریافت تازهٔ بسته‌ها از Dockerfile مشترک تکرار شد. دانلود بسته‌های npm پیش رفت؛ دریافت runtime قفل‌شدهٔ Node از `unofficial-builds.nodejs.org` به timeout/TLS EOF رسید. تلاش استفاده از تنظیم جایگزین runtime با frozen lockfile سازگار نبود و کنار گذاشته شد؛ آن تنظیم در کد نهایی وجود ندارد. package.json، lockfile، نسخهٔ Node/pnpm و اعتبارسنجی TLS تغییر نکردند.
- تکرار نهایی نصب و ساخت، از همان Dockerfile، با شبکهٔ معمول و کش کامل همان وابستگی‌ها موفق شد. `KARA_WEB_PACKAGES_BASE` به تصویر محلیِ کامل وابستگی اشاره داشت و `KARA_WEB_OFFLINE` روی پیش‌فرض false بود؛ pnpm با frozen lockfile و npm با ci اجرا شدند. پس از حذف `.next` قبلی، TypeScript، ۱۴ آزمون رابط، کامپایل کامل در ۷٫۳ دقیقه و ساخت لایه‌های production موفق شدند. کش فقط ورودی ابزارها/بسته‌ها بود؛ خروجی کامپایل کپی دستی نشد. موفقیت دریافت اینترنتی از صفر بدون cache، با این شواهد ادعا نمی‌شود.
- دیسک VM محلی از ۳۰ به ۴۵ گیگابایت افزایش یافت و swap موجود دوباره فعال شد. volume یا بانک برنامه حذف نشد. استفاده از کش اختیاری در [راهنمای رابط](persian-interface.md) توضیح داده شده است.
- در پایان فقط سه کانتینر متوقفِ تلاش‌های ناموفق همین اجرا و شاخهٔ کش موقت آن‌ها حذف شدند؛ تصویر اجرایی و کش کامل وابستگی حفظ شدند.

لاگ‌ها و تصاویر خصوصی در `.runtime/kp01-closeout/` خارج از Git هستند: `standard-offline-build.log` برای ساخت کامل آفلاین، `online-packages-retry.log` برای تلاش دریافت تازه و `final-standard-build.log` برای ساخت نهایی مشترک. این کش‌ها شرط ثابت پروژه یا فایل قابل اشتراک نیستند.

## آزمون و حفظ رفتار قبلی

- `make check`: ساختار، لینک‌ها و **۵۴ آزمون** موفق.
- **۴۷ آزمون PostgreSQL/API** روی `kara_kp01_restore` موفق؛ نقش‌ها، migration و بخش‌های قبلی دسترسی، اعضا، پروژه، کارتابل، اتوماسیون، قالب و آمادگی پوشش داده شدند.
- بررسی TypeScript و **۱۴ آزمون رابط/RTL** در ساخت کامل موفق شدند؛ این‌ها با دو مجموعهٔ بالا مجموعاً **۱۱۵ آزمون** هستند. آزمون HTTP و مرورگر علاوه بر این شمارند.
- HTTP با حساب‌های ساختگی و نشست/CSRF معتبر: ادمین کل و مدیر پروژه مجاز، editor/normal غیرمجاز برای تغییر نقش، جداسازی پروژه، فقدان کلید اقدام، replay، تعارض payload/revision و دو PUT هم‌زمان با نتایج 200/409 موفق بودند.
- مرورگر با تصویر تولیدی: نام/لوگوی Kara و عنوان پروژه/اعضا/ورود صحیح؛ ورود به پروژه، دو اجرای قبلی کارتابل، اتوماسیون موجود در حالت متوقف با سابقهٔ موفق و سه قالب موجود بارگذاری شدند. اتوماسیون فعال یا فرایند تازه اجرا نشد.
- مدیر ساختگی برای عضو editor نقش‌های PO و TL را ذخیره کرد؛ پس از reload باقی ماندند و نقش فنی عضو ثابت بود. جستجوی اعضا کار کرد. عضو normal همان نقش‌ها را دید؛ fieldset و تمام checkboxها عملاً disabled بودند و دکمهٔ ذخیره نداشت. شاهد خصوصی `roles-readonly-kara.jpg` و `reader-proof.json` ثبت شدند.
- تغییر نقش و آزمون‌های تغییردهنده فقط روی بانک بازیابی‌شده انجام شدند. نشست‌های ساختگی logout و بسته شدند؛ API و پردازشگرها پس از آزمون به تنظیمات عادی بانک اصلی برگشتند.
- روی تصویر نهایی، `make doctor` موفق شد: تصویرهای جاری، API با pong، HTML فارسی/RTL با HTTP 200، پورت‌های loopback و اتصال sandbox سازگار. Celery به inspect ping پاسخ داد. خواندن بانک اصلی، **۳ پروژه، صفر نقش کاری، صفر حساب ساختگی KP-01 و یک Trigger متوقف** را تأیید کرد.
- smoke نهایی مرورگر روی بانک اصلی: سه پروژه با نشست اصلی دیده شدند؛ عنوان «پروژه‌ها - Kara»، تصویر wordmark با بارگذاری موفق و favicon از `/kara/favicon.svg` تأیید شدند. کلاینت روی `http://localhost:8080` روشن ماند. fingerprint تصویر `501aa697b00b198d79ca5d5c536ccfe636c92285d3b89dd908bcf15235a2caa4` با سورس فعلی سازگار است.
