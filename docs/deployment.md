# استقرار کارا روی VDI یا سرور

## مهاجرت بانک در نصب تازه

سرویس یک‌باراجرای `migration` از تصویر اصلی نسخهٔ قفل‌شده و تنظیمات بانک همان محیط استفاده می‌کند. پس از آماده‌شدن PostgreSQL و Redis، فرمان `flask db upgrade` اجرا می‌شود. سرویس‌های API، Worker، Beat و WebSocket فقط پس از خروج موفق آن شروع می‌شوند؛ شکست مهاجرت مانع شروع آن‌ها می‌شود. این ترتیب در مسیر Compose و Make مشترک است و نیازی به حذف بانک یا volume نیست.

بانک پشتیبانی‌شدهٔ این راه‌انداز PostgreSQL است. برای ارتقای محیط دارای داده، ابتدا پشتیبان بگیرید؛ مهاجرت جایگزین پشتیبان‌گیری نیست. `docker compose down` داده‌ها را حفظ می‌کند؛ برای رفع خطای نصب از `down -v` یا پاک‌سازی volume استفاده نکنید.
