# ارزیابی اولیهٔ تحلیلگر روی مدل شرکت

تاریخ اجرا: ۷ اکتبر ۲۰۲۶. ورودی‌ها فقط سه درخواست ساختگی [DEMO-01 تا DEMO-03](../fixtures/requirements) بودند؛ هیچ درخواست واقعی جیرا یا دادهٔ مشتری ارسال نشد. برچسب‌های `expected` به مدل داده نشدند.

## روش و حدود بررسی

کد آماده‌سازی ورودی محلی اجرا شد؛ دستورالعمل تحلیلگر و متن ورودی گره تحلیل، مستقیماً به API شرکت فرستاده شدند و پاسخ نهایی از کد نهایی‌سازی محلی عبور کرد. توکن از تنظیمات خصوصی خوانده شد و در آرگومان‌ها، خروجی نمایشی یا Git قرار نگرفت. نتیجه‌ها در پوشهٔ خصوصی `.runtime/evaluations/` با دسترسی محدود نگهداری می‌شوند؛ اطلاعات اتصال، پاسخ‌های خام و متن استدلال داخلی در این سند ثبت نشده‌اند.

این روش کیفیت دستورالعمل و رفتار دو گره پایتون را بررسی می‌کند. این نوبت بررسی، ورود فایل، تنظیم تأمین‌کننده، اجرای گره کد در محیط محدود Dify، ثبت اجرای فرایند و رابط کاربری را پوشش نمی‌دهد. اجرای بعدی در [گزارش Dify](klassor-analysis-dify-evaluation.md) جداگانه ثبت شده است. ساختار پنج گره با مدل‌های دادهٔ Dify نصب‌شدهٔ 1.17.1 جداگانه معتبر بود؛ تابع جداسازی استدلال آن نیز با یک متن ساختگی بررسی شد.

«توکن پاسخ» مقدار گزارش‌شدهٔ API است و لزوماً فقط متن قابل مشاهده را نمی‌شمارد. در هر سه خروجی، بخش‌های ۱ تا ۹ حاضر بودند؛ بخش ۱۰ با رکورد تصمیمِ تولیدشده توسط بستر و وابسته به شناسهٔ تحلیل جایگزین شد. طبقه‌بندی صحیح یا حضور عنوان‌ها به معنی قبولی کامل محتوای نیازمندی نیست.

## موارد لازم برای بازبینی انسانی

- در DEMO-01، با وجود ثبت «رفتار فعلی: نامشخص»، جملهٔ مسئله نبودِ نمایش تعداد را به صورت واقعیت بیان می‌کند. این ادعا از ورودی ثابت نشده است. سؤال دربارهٔ رفتار تعداد در صفحه‌بندی نیز با توجه به تعریف «تعداد کل» تکراری است.
- در DEMO-03، نام فیلدهای پیشنهادی API و فرض امکان افزودن آن بدون تغییر قرارداد، تأیید فنی ندارند. چند مورد خارج از محدوده، مثل چاپ اسناد و بهینه‌سازی سرور، بیش از متن درخواست‌اند؛ نباید به عنوان توافق ثبت شوند.
- در DEMO-01، معیار مستقل برای جلوگیری از نمایش پاسخ جستجوی قدیمی در جستجوی فعلی صریح نیست. هنگام بازبینی معیارها، پوشش این رفتار باید بررسی و تکمیل شود.
- در DEMO-02، پیشنهادهای بهبود گسترده‌اند و تا پاسخ مالک محصول، دامنهٔ مصوب یا معیار پذیرش نهایی محسوب نمی‌شوند.

بنابراین این نسخه برای آزمایش و بررسی پیش‌نویس مناسب است؛ پذیرش خودکار تحلیل یا تولید بستهٔ اجرایی از آن تأیید نشده است. پیشنهادهای مدل باید با متن اصلی مقایسه و فرض‌ها، محدوده و معیارهای پذیرش اصلاح شوند. تصمیم واقعی مالک محصول همچنان جداگانه و برای همان نسخه لازم است.

## بررسی باقی‌مانده

سه نمونه پس از این نوبتِ API در خود Dify اجرا شدند؛ نتیجه‌ها و اصلاح دستورالعمل ۰٫۴ در [گزارش Dify](klassor-analysis-dify-evaluation.md) ثبت شده‌اند. این سند همچنان فقط نتایج اجرای مستقیم API را گزارش می‌کند. پذیرش معنایی، ثبت تصمیم واقعی مالک محصول و اتصال جیرا باقی‌اند.
