# انتخاب مدل و Runner برای گام‌های برنامه

در اجرای دستی Workflow، کاربر برای **هر گام LLM** یک اتصال مدل شخصی و برای **هر گام اجرایی** یک Runner شخصی انتخاب می‌کند. انتخاب خالی به مدل پیش‌فرض تبدیل نمی‌شود. یک اتصال یا دستگاه می‌تواند برای چند گام انتخاب شود؛ گام‌های متفاوت می‌توانند مدل‌ها و دستگاه‌های متفاوت داشته باشند.

در ویرایش مرحلهٔ فلو، تب «روش اجرا» فهرست گام‌های نسخهٔ انتخاب‌شده و نیاز هر کدام به مدل و Runner را نشان می‌دهد. انتخاب‌های شخصی مجری در فرم شروع اجرا انجام می‌شوند؛ انتخاب مدل و دستگاه یک نفر در تعریف مشترک تیم ذخیره نمی‌شود. دیالوگ‌های فلو و مرحله فضای بیشتری دارند و محتوای تب فعال مستقل اسکرول می‌شود.

## مدل هر گام

- هر LLM یک انتخاب الزامی با عنوان همان گام دارد. فقط مدل‌های chat شخصی سازگار با قابلیت‌های همان گام نمایش داده می‌شوند. نیازهای مشترک اعلام‌شده در Start نیز بر هر LLM اعمال می‌شوند.
- مالکیت اتصال، عضویت، قابلیت‌ها و پارامترهای همان گام در سرور بررسی می‌شوند. نیاز JSON یک گام، به مدل گام دیگری تحمیل نمی‌شود. پارامتر ناسازگار یا خارج از محدوده بی‌صدا حذف نمی‌شود.
- گزینهٔ Start برای به‌تعویق‌انداختن انتخاب مدل، اجازه می‌دهد برنامه بدون مدل مشخص ساخته و منتشر شود. اجرای دستی برنامه‌های فعلی نیز انتخاب مستقل مدل‌ها را دریافت می‌کند؛ نسخهٔ منتشرشده بازنویسی نمی‌شود.
- اتصال‌ها از «تنظیمات و اتصال‌ها ← اتصال به مدل هوش مصنوعی» مدیریت می‌شوند. دریافت فهرست مدل‌ها ممکن است metadata افزونه را بخواند؛ inference ایجاد نمی‌کند.

## دستگاه هر گام

LLM، کد، قالب متن، درخواست وب و جست‌وجوی دانش به انتخاب Runner نیاز دارند. Start، شرط، ادغام متغیرها و خروجی، Runner جدا ندارند و روی دستگاه هماهنگ‌کننده اجرا می‌شوند. Runner اولین گام اجرایی در ترتیب تعریف گراف، هماهنگ‌کننده است. ترتیب وابستگی‌ها و شاخه‌های فعال را حفظ می‌کند و گام راه‌دور را به دستگاه انتخاب‌شده می‌سپارد. سرور فقط مجوز، صف و نتیجه را مدیریت می‌کند.

برای هر دستگاه می‌توان یک آماده‌سازی موفق سورس روی **همان دستگاه** انتخاب کرد یا صریحاً بدون سورس آماده ادامه داد. گام‌های یک دستگاه در یک اجرا سورس آمادهٔ مشترک دارند. گزینهٔ سورس هارنس مستقل است و همچنان از سیاست منتشرشدهٔ مرحله پیروی می‌کند.

Runner باید قابلیت `node-routing-v1` و قابلیت لازم گام، مانند Python/JavaScript یا HTTP، را داشته باشد. بستهٔ تازه را از تنظیمات دریافت و Runner را دوباره راه‌اندازی کنید. دستگاه فاقد قابلیت لازم در انتخاب همان گام نمایش داده نمی‌شود؛ مالکیت و قابلیت‌ها در سرور نیز بررسی می‌شوند. نبود یا قطع Runner جایگزین سروری ایجاد نمی‌کند.

## قرارداد، صف و سابقه

ورودی رزروشدهٔ `__kara_model_connection` در اجراهای جدید رشتهٔ JSON زیر را دریافت می‌کند:

```json
{
  "version": 2,
  "models": {"llm-node-id": "personal-model-connection-uuid"},
  "runners": {
    "llm-node-id": {"device_id": "personal-device-uuid", "source_job_id": null}
  }
}
```

کلیدهای مدل باید دقیقاً گام‌های LLM و کلیدهای Runner دقیقاً گام‌های اجرایی همین نسخه باشند. اعتبارنامه، URL یا تنظیمات خام مدل پذیرفته نمی‌شوند. انتخاب‌های اجرا از ورودی‌های کاری، تحویل مراحل و digest تصمیم‌های انسانی جدا می‌مانند.

در ایجاد تلاش تیمی، revision مدل‌های انتخاب‌شده با metadata داخلی `__kara_execution_selection` ثابت می‌شود. ارسال این metadata توسط کلاینت رد می‌شود. تغییر یا حذف اتصال، عضویت، نسخهٔ برنامه یا لغو دستگاه، ادامهٔ همان اجرا را متوقف می‌کند. تنظیمات تازه بی‌صدا جای انتخاب قبلی نمی‌نشینند. مدل و Runner هر گام در snapshot و سابقه ثبت می‌شوند؛ توکن در snapshot قرار نمی‌گیرد و فقط در حافظهٔ دستگاه مقصد همان گام خوانده می‌شود.

تلاش‌ها و snapshotهای قدیمی با انتخاب تک‌مدلی/تک‌دستگاهی خود ادامه می‌یابند. شروع خودکار موجود نیز قرارداد قبلیِ حساب اجراکننده، مدل شخصی و Runner پروژه را حفظ می‌کند؛ الزام انتخاب تعاملی جدید از مسیر شروع دستی و تلاش جدید تیمی اعمال می‌شود. این سازگاری مجوز اجرای سروری یا توکن مشترک ایجاد نمی‌کند.

## محدودیت و بررسی

محدودیت‌های قرارداد Runner دربارهٔ نوع گره، vision، چرخه‌ها و روش بازیابی دانش حفظ شده‌اند. این تغییر پشتیبانی از گرهٔ جدید ایجاد نمی‌کند. مدل‌های embedding/rerank دانش همچنان از اتصال شخصی سازگار با تنظیمات همان دانش استفاده می‌کنند.

آزمون‌های قطعی سرور و پیمایش گراف، انتخاب دو مدل/دو دستگاه، مالکیت، قابلیت‌ها، ثابت‌ماندن revision، انتقال خروجی بین گام‌ها، تکرار امن درخواست و توقف پس از لغو را بررسی می‌کنند. تست کلاینت، مرورگر و اجرای واقعی مدل/کد روی دو دستگاه طبق درخواست کاربر انجام نشده‌اند.
