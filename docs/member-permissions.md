# کنترل مجوز تغییر نقش کاربران

مدیریت کاربران از حساب‌ها و عضویت‌های اصلی Dify استفاده می‌کند. حساب یا رمز موازی ساخته نمی‌شود. در نسخهٔ پایهٔ ۱.۱۷.۱، مسیر سازگاری نقش‌های Community در `RBACService.MemberRoles.replace` پیش از نوشتن نقش، مجوز مدیریت عضو را کنترل نمی‌کرد. افزونهٔ بستر این کنترل را در سمت سرور اضافه می‌کند.

- در پروژهٔ مستقل، تغییر نقش فقط برای مالک همان پروژه یا مالک محصول مجاز است؛ نقش مدیر فنی به‌تنهایی کافی نیست. فضای کاری قدیمیِ خارج از پروژه‌های محصول از سیاست اصلی Dify پیروی می‌کند.
- عضو باید متعلق به همان فضای کاری باشد.
- کاربر از این مسیر نقش خودش، مالک پروژه یا مالک محصول را تغییر نمی‌دهد.
- فقط یک نقش معتبر غیرمالک پذیرفته می‌شود. مالک محصول، مالک پروژه را از مسیر اختصاصی صفحهٔ پروژه تعیین می‌کند؛ انتقال مالکیت اصلی Dify برای پروژه‌های محصول بسته است.
- شاخهٔ Enterprise RBAC همچنان از سرویس اصلی Dify استفاده می‌کند.

کنترل در تصویر اختصاصی API نصب می‌شود؛ سورس upstream و جدول‌های حساب تغییر نمی‌کنند. شناسه و مجوزهای نقش‌های Dify حفظ می‌شوند.

آزمون یکپارچگی در تصویر API با پنج آزمون، حساب‌ها و فضای کاری ساختگی اجرا می‌شود. حتی commit داخلی سرویس Dify داخل savepoint قرار می‌گیرد و تراکنش بیرونی در پایان هر آزمون rollback می‌شود. داده‌های اعضای واقعی، رمز و اتصال ایمیل در این آزمون تغییر نمی‌کنند.

برای اجرای آزمون، پس از ساخت تصویر و آماده بودن سرویس بانک داده:

```sh
PYTHONPATH=scripts .venv/bin/python -c 'from local_dify import compose; compose(["run", "--rm", "--no-deps", "--entrypoint", "python", "api", "-m", "unittest", "company_members.test_access"])'
```
