# پروژه‌ها در Dify شرکت

هر فضای کاری می‌تواند چند پروژه داشته باشد. نام پروژه در همان فضای کاری یکتا است و هر برنامه حداکثر به یک پروژه تعلق دارد. برنامه‌های قبلی بدون تغییر محتوا در استودیو باقی می‌مانند و می‌توان آن‌ها را به پروژه وصل کرد.

پروژه‌ها فرایندهای Workflow و Chatflow و ایجنت‌های Dify را گروه‌بندی می‌کنند. اعضا، ارائه‌دهندگان مدل و تنظیمات فضای کاری مشترک‌اند؛ پروژه در این نسخه مرز مستقل مجوز دسترسی، کلید API یا دانش نیست. نمایش و ویرایش برنامه‌ها همچنان از مجوزهای Dify پیروی می‌کند. کاربر دارای مجوز مدیریت برنامه‌های فضای کاری می‌تواند پروژه بسازد و برنامه‌ها را سازمان‌دهی کند.

## استفاده در رابط فارسی

۱. از منوی «پروژه‌ها»، «ساخت پروژه» را انتخاب و نام و توضیح را ذخیره کنید.

۲. در صفحهٔ پروژه، «ساخت برنامه» را بزنید و فرایند، گفتگو با فرایند یا ایجنت بسازید. برنامه بلافاصله به همان پروژه وصل می‌شود. ویرایشگر جدید ایجنت، در صورت فعال بودن قابلیت متناظر Dify، نیز قابل انتخاب است.

۳. «باز کردن برنامه» ویرایشگر و مسیر مجاز همان برنامه در Dify را باز می‌کند؛ تنظیم مدل، ابزارها، دستورالعمل، مراحل و انتشار از ویرایشگر معمول Dify انجام می‌شود.

۴. با «افزودن برنامهٔ موجود» برنامه‌ای از فضای کاری انتخاب کنید. اگر قبلاً در پروژهٔ دیگری است، انتقال به تأیید صریح داخل رابط نیاز دارد و پروژهٔ قبلی نمایش داده می‌شود.

۵. فیلترهای «فرایندها» و «ایجنت‌ها» فقط برنامه‌های همین پروژه را نشان می‌دهند. تغییر نام پروژه ارتباط برنامه‌های آن را حفظ می‌کند. «خروج از پروژه» برنامه را حذف نمی‌کند.

استودیو همچنان فهرست عمومی برنامه‌های فضای کاری است. برنامه‌هایی که هنوز به پروژه وصل نشده‌اند، از همان فهرست و انتخابگر پروژه در دسترس هستند. ساخت پروژه یا برنامه به معنی تکمیل و آزمایش دستورالعمل ایجنت یا انتشار خودکار آن نیست.

## پیاده‌سازی و راه‌اندازی

تصویر اختصاصی API از `langgenius/dify-api:1.17.1` ساخته می‌شود. تغییرات در `infra/api/` نگهداری می‌شوند؛ سورس upstream در `.runtime/dify` تغییر نمی‌کند. نصب‌کننده تطابق نقاط اتصال را کنترل می‌کند تا تغییر نسخه بدون بررسی پذیرفته نشود.

سه جدول `company_projects`، `company_project_apps` و `company_project_schema` به بانک داده اضافه می‌شوند. ساخت جدول‌ها نسخه‌دار، تکرارپذیر و برای شروع هم‌زمان سرویس‌ها در PostgreSQL قفل‌شده است. جدول‌های اصلی Dify تغییر نمی‌کنند. ساخت برنامه و ثبت پروژهٔ آن پیش از commit سرویس اصلی، در یک تراکنش انجام می‌شود.

`make up` تصویرهای لازم را می‌سازد و سرویس‌های API، worker، worker_beat و api_websocket از نسخهٔ یکسان استفاده می‌کنند. `make doctor` تطابق تصویرهای فعال با فایل‌های مخزن را کنترل می‌کند.

قبل از اولین راه‌اندازی این تغییر، از PostgreSQL و فایل‌های محیط خود نسخهٔ پشتیبان بگیرید. بانک داده و نسخهٔ پشتیبان وارد Git نمی‌شوند. برگشت به نسخهٔ قبلی تصویرها، جدول‌های افزوده را حذف نمی‌کند و برنامه‌های اصلی Dify را حفظ می‌کند.

## اتصال‌های داخلی

API کنسول زیر `/console/api/company/projects` قرار دارد و از ورود کاربر، فضای کاری فعال، بررسی مجوز و محافظت CSRF استاندارد Dify استفاده می‌کند. اتصال مدل یا توکن جداگانه‌ای برای پروژه‌ها لازم نیست.

- فهرست و ساخت پروژه: مسیر پایه.
- مشاهده و تغییر نام/توضیح: `/<project_id>`.
- فهرست و ساخت برنامهٔ پروژه: `/<project_id>/apps`.
- اتصال/انتقال یا خروج از پروژه: `/<project_id>/apps/<app_id>` با PUT یا DELETE.
- برنامه‌های قابل انتخاب در فضای کاری: `/resources`، صفحه‌بندی‌شده و محدود به برنامه‌های قابل مشاهدهٔ کاربر.

خروج از پروژه فقط ارتباط را حذف می‌کند؛ محتوای برنامه و اجرای آن در Dify حفظ می‌شود. انتقال برنامه، پروژهٔ قبلی آن را جایگزین می‌کند.

آزمون‌های ذخیره‌سازی با بانک SQLite واقعی، ماندگاری پس از اتصال دوباره، جداسازی فضای کاری، یکتایی نام، انتقال، تغییر نام و rollback تراکنش را بررسی می‌کنند. بررسی عملی روی محیط PostgreSQL و رابط وب نیز هنگام تحویل قابلیت انجام می‌شود.

## بررسی نسخهٔ محلی — ۱۰ اکتبر ۲۰۲۶

۱۵ آزمون بستر و ذخیره‌سازی، بررسی نوع‌های صفحه‌ها و اتصال‌های جدید، ۵۹۴۷ کلید ترجمه، شش آزمون RTL و ساخت کامل تصویر وب موفق شدند. `make up` و `make doctor` پس از آماده شدن API موفق بودند؛ مسیرهای جدید برای کاربر ناشناس HTTP 401 دادند.

در مرورگر، دو پروژهٔ نمونه، یک فرایند و دو نوع ایجنت ساخته شدند. فیلتر ایجنت‌ها، انتقال بین پروژه‌ها، خروج بدون حذف برنامه، اتصال دوباره، تغییر نام و توضیح و ماندگاری پس از بارگذاری دوباره بررسی شدند. ویرایشگر فرایند و ویرایشگر جدید ایجنت از صفحهٔ پروژه درست باز شدند. این نمونه‌ها پیش‌نویس‌اند؛ فراخوانی مدل، اجرای فرایند و انتشار آن‌ها موضوع این آزمون نبود.
