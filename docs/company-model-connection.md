# اتصال خصوصی به API مدل شرکت

این مرحله، فراخوانی مستقیم API از محیط اجرای افزونهٔ Dify را بررسی می‌کند. اجرای موفق این بررسی به‌تنهایی به معنی نصب ارائه‌دهنده یا اتصال یک گردش‌کار Dify نیست.

## نگهداری اطلاعات اتصال

فایل واقعی اتصال در `.runtime/company-model/connection.local.json` قرار می‌گیرد. قواعد موجود `.runtime/` و `*.local.json` آن را از Git خارج می‌کنند. پوشه دسترسی `700` و فایل دسترسی `600` دارد. ابزار بررسی، فایل داخل Git یا دارای دسترسی گروه و دیگران را نمی‌پذیرد.

فقط تنظیمات لازم ذخیره شوند: آدرس پایه، نام مدل، توکن و هدرهای مورد نیاز. پاسخ کامل حساب، اطلاعات مالک و موقعیت کاربر در فایل اتصال ذخیره نمی‌شوند. قالب قابل اشتراک [نمونهٔ اتصال](../infra/company-model.connection.example.json) فاقد اطلاعات واقعی محیط است.

برای محیط جدید:

```sh
mkdir -p .runtime/company-model
chmod 700 .runtime/company-model
cp infra/company-model.connection.example.json .runtime/company-model/connection.local.json
chmod 600 .runtime/company-model/connection.local.json
```

مقادیر واقعی فقط در فایل خصوصی تکمیل شوند؛ توکن در فرمان، پیام کامیت یا فایل نمونه قرار نگیرد.

## شکل فراخوانی

- `base_url` آدرس پایه، مانند `https://model.example.com/v1` است. ابزار، درخواست `POST` را به `/chat/completions` اضافه می‌کند.
- `model` نام مدل در بدنهٔ درخواست است.
- `api_token` مقدار توکن سرویس است؛ در هدر `Authorization: Bearer …` ارسال می‌شود، نه در بدنهٔ JSON. اگر توکن از پاسخ حساب گرفته شود، مقدار فیلد `result.apiToken` استفاده می‌شود.
- `extra_headers` هدرهای اضافی سرویس را نگهداری می‌کند و در قالب پیش‌فرض خالی است. در آزمون این محیط، حذف Cookie و سپس حذف هر سه هدر `x-client-id`، `x-request-id` و `x-user-id` همچنان پاسخ معتبر داد. تنظیمات خصوصی اکنون فقط از Bearer استفاده می‌کنند؛ این نتیجه مربوط به همین مدل، توکن و درخواست آزمایشی است.
- اگر محیط دیگری به Cookie یا هدر اضافی نیاز داشت، مقادیر آن فقط در همین فایل خصوصی قرار می‌گیرند.

## بررسی از محیط Dify

```sh
python3 scripts/check_company_model.py --validate-only
make check-model
```

پیش‌نیاز فراخوانی واقعی: Docker و سرویس افزونهٔ Dify در حال اجرا باشند. نام پیش‌فرض کانتینر `company-agent-local-plugin_daemon-1` است؛ برای محیط متفاوت، از `--container` استفاده شود.

توکن از ورودی استاندارد به کانتینر می‌رود و در آرگومان فرمان یا متغیر محیط قرار نمی‌گیرد. اتصال HTTPS با اعتبارسنجی گواهی انجام می‌شود؛ تغییر مسیر HTTP دنبال نمی‌شود. بدنهٔ پاسخ، کوکی، توکن و متن خطای سرویس در خروجی چاپ نمی‌شوند.

موفقیت نیازمند HTTP 200 و پاسخ `choices[0].message` با نقش `assistant` و متن غیرخالی است. خطای HTTP، پایان مهلت، خطای TLS و پاسخ نامعتبر موفقیت محسوب نمی‌شوند. این ابزار فقط درخواست ساختگی فارسی و بدون streaming می‌فرستد؛ آزمون‌های جداگانهٔ سازگاری این محیط در بخش وضعیت ثبت شده‌اند.

`make check` آزمون‌های بدون شبکهٔ این ابزار را اجرا می‌کند. `make check-model` جداگانه و با اطلاعات خصوصی، یک فراخوانی واقعی انجام می‌دهد.

## انتخاب ارائه‌دهنده در Dify

API در آزمون واقعی، پاسخ Chat Completions و پاسخ جریانی SSE معتبر داد. در بررسی سورس رسمی افزونهٔ `langgenius/openai_api_compatible` نسخهٔ `0.0.68`، فیلدهای `endpoint_url`، `api_key`، `endpoint_model_name` و حالت `chat` وجود دارند. این ارائه‌دهنده گزینهٔ مناسب برای مرحلهٔ بعد است؛ هدرهای اضافی در آزمون فعلی لازم نبودند. [طرح فرم رسمی](https://github.com/langgenius/dify-official-plugins/blob/main/models/openai_api_compatible/provider/openai_api_compatible.yaml)، [منطق فراخوانی مدل](https://github.com/langgenius/dify-official-plugins/blob/main/models/openai_api_compatible/models/llm/llm.py)

در فرم مدل، آدرس پایهٔ خصوصی به‌عنوان API Base URL، توکن خام به‌عنوان API Key، نام مدل خصوصی به‌عنوان نام مدل و حالت Chat Completions انتخاب شوند. پیشوند Bearer در مقدار API Key وارد نمی‌شود. نصب ارائه‌دهنده، اعتبارسنجی فرم و اجرای یک گردش‌کار Dify هنوز انجام نشده‌اند. هیچ توکن یا کوکی در گردش‌کار قابل export قرار نمی‌گیرد.

## وضعیت اجرای این محیط

در آزمون مجدد ۲۰۲۶-۱۰-۰۷ از سرویس افزونهٔ Dify، نمونهٔ کامل، نمونهٔ بدون Cookie و نمونهٔ فقط Bearer، همگی HTTP 200 و متن غیرخالی assistant دریافت کردند. پاسخ جریانی نیز HTTP 200، قطعه‌های دارای متن و پایان `[DONE]` داشت.

در آزمون جداگانهٔ `max_tokens=5`، HTTP 200 دریافت شد اما متن نهایی خالی بود. با `max_tokens=512` متن غیرخالی و پایان `stop` دریافت شد. مدل در این پاسخ فیلد `reasoning_content` داشت؛ متن آن ذخیره یا چاپ نشد. برای اجرای آزمایشی، سقف بسیار کوچک پاسخ استفاده نشود؛ ۵۱۲ برای همین درخواست کوتاه آزمایش شده و اندازهٔ واقعی پنجرهٔ زمینه را مشخص نمی‌کند.

نتیجهٔ بررسی‌ها فقط در `.runtime/company-model/last-check.local.json` نگهداری می‌شود. نام مدل، آدرس و توکن واقعی در مستند مشترک ثبت نمی‌شوند. این آزمون‌ها فراخوانی مستقیم API از کانتینر هستند؛ اتصال ارائه‌دهنده و گردش‌کار داخل Dify، ابزارها و خروجی ساختاریافته هنوز تأیید نشده‌اند.
