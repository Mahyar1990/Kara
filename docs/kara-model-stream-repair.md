# حفظ علت پایان پاسخ مدل

SDK نصب‌شدهٔ `dify-plugin 0.10.2` در افزونهٔ ثابت `openai_api_compatible 0.0.68` مقدار پایان پاسخ را با `null` قطعهٔ usage بازنویسی می‌کرد. اصلاح عمومی Kara فقط مقدار غیر null رسیده از ارائه‌دهنده را نگه می‌دارد؛ `stop` تولید یا حدس زده نمی‌شود. `length`، مقدار خالی، قطع جریان و نبود علت پایان همچنان پذیرش موفق نیستند.

`python scripts/model_stream.py` فقط بررسی می‌کند؛ `--apply` اصلاح را اعمال و daemon افزونه را restart می‌کند. `make up` همین اصلاح را پس از راه‌اندازی اعمال و `make doctor` صحت آن را کنترل می‌کند. هیچ‌کدام مدل را فراخوانی نمی‌کنند. افزونه باید پیش‌تر نصب شده باشد؛ بعد از نصب جدید دوباره این فرمان اجرا شود.

ابزار فقط فایل SDK نصب‌شده در storage سرویس افزونه را با hash کامل شناخته‌شده و مسیر ثابت بررسی می‌کند. فایل جایگزین اتمی است تا cache مشترک uv تغییر نکند. سورس upstream در `.runtime/dify`، فایل‌های provider و اعتبارنامه‌ها تغییر نمی‌کنند. نسخه یا hash ناشناخته رد می‌شود و به بازبینی جدا نیاز دارد؛ این اصلاح برای نسخه‌های دیگر ادعای پوشش ندارد.

آزمون آفلاین حفظ stop و length و tool_calls، null و فقدان علت پایان را پوشش می‌دهد. پذیرش واقعی Workflow به اجرای مدل و بررسی خروجی مستقل نیاز دارد و از این اصلاح نتیجه نمی‌شود.

در بررسی ۲۳ اکتبر ۲۰۲۶، اصلاح روی SDK نصب‌شده اعمال شد و daemon افزونه restart شد. دو آزمون parser واقعی داخل venv افزونه با SSE ساختگی، حفظ usage و علت پایان و رد نبود علت پایان را تأیید کردند؛ هیچ HTTP به مدل ارسال نشد. ۵۶ آزمون `make check`، پیکربندی Compose و `make doctor` موفق بودند.
