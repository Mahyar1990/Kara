# شاخه‌های بستر و ایجنت‌ها

## مرز تغییرات

| شاخه | محتوای قابل نگهداری |
| --- | --- |
| `master` | بستر Kara و تمام بررسی‌ها، نیازمندی‌ها، طراحی فرایند و برنامه‌ریزی‌های فعلی؛ شامل اسناد آمادگی و برنامهٔ آیندهٔ کلاسور |
| `agents` | تمام محتوای بستر مشترک، به‌اضافهٔ قالب‌ها و فرایندها، دستورالعمل نقش‌ها، زمینهٔ فنی، نمونه‌ها، تست‌ها و گزارش‌های ایجنت‌ها |
| `clasor-agents` | رزرو برای پیاده‌سازی آیندهٔ کلاسور و دارایی‌های مرتبط؛ پیش از شروع پیاده‌سازی هیچ کامیت اختصاصی نسبت به master نداشته باشد |

قراردادها و نمونه‌های عمومی بستر، از جمله `kara_contracts/` و `fixtures/kara-contracts/`، متعلق به `master` هستند. فایل `AGENTS.md` دستورالعمل همکاری با مخزن است و در هر دو شاخه وجود دارد. پیاده‌سازی ایجنت‌ها در `prompts/`، `workflows/` و `fixtures/`، ابزارهای ساخت و بررسی آن‌ها در `scripts/` و مستندات مرتبط در `docs/`، متعلق به شاخهٔ `agents` هستند. این فایل‌ها در تاریخچهٔ `master` قرار ندارند.

## انتخاب شاخه

برای کار روی بستر:

```sh
git switch master
git switch -c feat/dify-your-topic
make check
```

برای کار روی ایجنت:

```sh
git switch agents
git switch -c feat/agent-your-topic
make check
```

قبل از تغییر شاخه، کار ناتمام را در شاخهٔ مربوط ثبت یا به روشی قابل بازیابی نگهداری کنید. هر کامیت همچنان فقط یک کار مستقل را ثبت می‌کند. فایل تنظیمات شخصی، توکن، پاسخ واقعی مدل و دادهٔ Kara خارج از Git می‌مانند.

مقصد MR تغییرات Kara، `master` و مقصد MR تغییرات ایجنت‌ها، `agents` است. برای دریافت تغییرات جدید بستر، `master` در `agents` ادغام می‌شود؛ پس از اضافه‌شدن Remote، این ادغام نیز با MR و تأیید دستی TL انجام می‌شود. کل شاخهٔ `agents` در `master` ادغام نشود، زیرا ایجنت‌ها دوباره وارد شاخهٔ بستر می‌شوند.

## جداسازی تاریخچهٔ موجود

در ۲۰۲۶-۱۰-۰۹، بخش‌های بستر و ایجنتِ کامیت‌های قبلی جدا شدند و شاخهٔ `main` به `master` تغییر نام داد. کامیت‌های بستر، از جمله فارسی‌سازی و اصلاح اتصال sandbox، روی `master` قرار گرفتند. کامیت‌های ایجنت با حفظ ترتیب، پیام تاریخی و هویت نویسنده، روی همان بستر بازچینی شدند. شناسهٔ کامیت‌های بازچینی‌شده تغییر می‌کند. شاخه‌های موضوعی قبلی نیز به کامیت متناظر در تاریخچهٔ جدید متصل می‌شوند.

نسخهٔ بازیابی Git پیش از جداسازی با `git bundle` تهیه و اعتبارسنجی شد. فایل آن و نگاشت شناسه‌های قدیم به جدید در `.runtime/git-reorganization-2026-10-09/` خصوصی و خارج از Git نگهداری می‌شوند. این بازچینی محلی است؛ مخزن هنوز Remote ندارد.

برنامه‌های واردشده در Kara داخل بانک دادهٔ محیط محلی نگهداری می‌شوند. تغییر شاخهٔ Git، فهرست برنامه‌های استودیو را تغییر نمی‌دهد. جداسازی حاضر مربوط به کد، فایل‌های قابل اشتراک و تاریخچه است؛ محیط و دادهٔ اجرای Kara مستقل از شاخه نگهداری می‌شوند.

## شاخهٔ اختصاصی کلاسور — تصمیم اصلاح‌شدهٔ ۲۱ اکتبر ۲۰۲۶

کار فعلی، بررسی و آماده‌سازی Kara است. تمام بررسی‌ها، نیازمندی‌ها، طراحی فرایند و برنامه‌های پیش از پیاده‌سازی روی `master` ثبت می‌شوند؛ نام کلاسور در یک سند، دلیل ثبت آن روی شاخهٔ پیاده‌سازی نیست.

`clasor-agents` برای شروع آیندهٔ پیاده‌سازی اختصاصی ایجنت‌های کلاسور رزرو است. اکنون باید به همان commit شاخهٔ `master` اشاره کند؛ بنابراین اختلاف کامیت و محتوا نسبت به شاخهٔ اصلی صفر است. تا آغاز واقعی پیاده‌سازی، کامیت جدیدی روی این شاخه ساخته نشود. کار جاری روی `master` ادامه می‌یابد.

پنج کامیت برنامه‌ریزی این گفتگو با حفظ ارجاع به مبدأ، جداگانه به `master` منتقل شدند. نام و هویت محصول، مدل کارکرد، برنامهٔ ساخت، اصلاح نام‌گذاری و برنامهٔ آمادگی حفظ شدند. تاریخچهٔ پیشین `agents` و `clasor-analysis-agents` وارد `master` نشد و روی همان شاخه‌ها باقی ماند. منابع وابستهٔ آن تاریخچه از مستندات با ارجاع به نسخهٔ اصلی در دسترس‌اند.

| کامیت مبدأ | کامیت منتقل‌شده به master | موضوع |
| --- | --- | --- |
| `4f93ee8` | `1f10683` | نام Kara و سیاست شاخه‌ها |
| `ce53de9` | `fe20575` | مدل کارکرد Kara |
| `9da7ad0` | `9559eaa` | برنامهٔ ساخت ایجنت‌های کلاسور |
| `35f5caa` | `cef53d9` | یکدست‌سازی هویت محصول |
| `f3f8076` | `4fdf4a0` | بررسی آمادگی و برنامهٔ تکمیل Kara |

نسخهٔ بازیابی پیش از انتقال در `.runtime/git-relocation-2026-10-21/` به‌صورت خصوصی نگهداری و اعتبارسنجی شد. انتقال محلی است و تغییری روی Remote ارسال نشده است.

پس از پذیرش هستهٔ Kara و آغاز واقعی ساخت ایجنت‌ها، شاخهٔ `clasor-agents` از آخرین مبنای اصلی ادامه می‌یابد. prompt، DSL، کد، نمونه، تست و مستند مرتبط با همان پیاده‌سازی در آن شاخه ثبت شوند. تغییرات عمومی خود Kara همچنان روی بستر اصلی انجام می‌شوند. ادغام کل تاریخچهٔ ایجنت‌ها در `master` انجام نشود.

برای بررسی خالی‌بودن اختلاف شاخه پیش از شروع پیاده‌سازی:

```sh
git rev-list --left-right --count master...clasor-agents
git diff --stat master clasor-agents
```

خروجی مورد انتظار در این مقطع `0 0` و diff خالی است. شاخهٔ Git، پروژه‌ها و بانک دادهٔ Kara را جدا نمی‌کند؛ آزمایش ایجنت‌ها در آینده در پروژهٔ آزمایشی مستقل انجام شود.

## شروع پیاده‌سازی اختصاصی — ۲۳ اکتبر ۲۰۲۶

پس از گام صفر پایلوت و درخواست بعدی کاربر، ساخت قرارداد اجرایی و نمونه‌های ارزیابی PA-04 روی `clasor-agents` آغاز شد. از این نقطه، داشتن کامیت اختصاصی این شاخه انتظار می‌رود؛ الزام اختلاف صفر در بخش قبل، مربوط به پیش از شروع ساخت بود. master همچنان بستر و برنامه‌ریزی مشترک را نگه می‌دارد و دارایی‌های `clasor_agents/` وارد آن نمی‌شوند. بستهٔ Workflow تخصصی PA-04 نیز آماده شده، اما پذیرش کیفیت مدل و بازخورد واقعی به علت ناسازگاری metadata اتصال مدل باقی‌اند؛ [گزارش گام ۲](clasor-pa04-workflow.md) مرجع وضعیت جاری است.
