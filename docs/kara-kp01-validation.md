# گزارش پذیرش KP-01 — هویت و نقش‌های کاری Kara

تاریخ: ۲۱ اکتبر ۲۰۲۶. مبنای بستر `9146e37` در `master`؛ دامنهٔ این کار نقش‌های کاری و تفکیک ادمین کل از PO است. ساخت ایجنت کلاسور در این گام انجام نمی‌شود.

## شواهد داده و مهاجرت

- محیط محلی Colima از وضعیت خاموش روشن شد. API و پردازشگرها برای تهیهٔ پشتیبان متوقف شدند. PostgreSQL با فرمت custom در `.runtime/kp01/before.dump` پشتیبان‌گیری و در `kara_kp01_restore` بازیابی شد؛ همهٔ حساب‌ها و سناریوهای تغییردهندهٔ آزمون در همین بانک جدا اجرا شدند.
- مهاجرت واقعی `001_team_roles` اعمال شد. تعداد و هش محتوای تک‌تک **۱۵۱ جدول قبلی** قبل و بعد یکسان بود. schema قدیمی مقدار ۱ دارد و نقش‌های کاری در بانک اصلی خالی‌اند؛ مدیر یا ادمین خودکار PO نشد.
- نسخهٔ قبلی تصویر API روی بانک آزمون ارتقایافته راه‌اندازی شد و schema قبلی و نقش‌های تازه را بدون تغییر داده خواند. این شاهد مربوط به بازگشت همین گام افزایشی است.
- آزمون‌های migration، اجرای دوباره و هم‌زمان دو runner، checksum تغییرکرده، نسخهٔ ناشناخته، شکست میانی DDL و حفظ ردیف‌های پروژه، نگاشت برنامه و عضویت را پوشش دادند.

## شواهد خودکار و HTTP

- `make check`: **۵۴ آزمون** موفق؛ کنترل فایل‌ها، لینک‌ها و exclusions نیز موفق است.
- مجموعهٔ PostgreSQL تصویر API: **۴۷ آزمون** موفق، شامل دسترسی، اعضا، پروژه، کارتابل، تصمیم انسانی، اتوماسیون، قالب، آمادگی و مهاجرت قبلی، به‌علاوهٔ نقش‌ها و مهاجرت جدید.
- TypeScript اجزای شرکت و کلاینت API و **۱۴ آزمون** رابط/RTL موفق‌اند.
- HTTP واقعی با حساب‌های ساختگی: نشست و CSRF، ادمین کل و مدیر پروژه، رد ویرایش عضو عادی و editor، مرز دو پروژه، کلید اقدام مفقود، replay یکسان، تعارض payload و revision. دو PUT هم‌زمان با نسخهٔ یکسان دقیقاً 200 و 409 دادند.
- حذف عضویت نقش‌ها را حذف و تاریخچه را حفظ می‌کند؛ حذف و عضویت مجدد، درخواست قدیمی را رد می‌کند. خطای بومی حذف کاربر غیرعضو با آزمون جدا حفظ شد. شکست ثبت audit کل تغییر نقش را rollback می‌کند.

## ساخت و بررسی کلاینت

ساخت استاندارد در دریافت وابستگی به timeout شبکه رسید. cache همان lockfile حفظ و دریافت با مهلت بیشتر تکمیل شد؛ وابستگی یا نسخهٔ upstream تغییر نکرد. کامپایل تولیدی Next.js با موفقیت انجام شد. ذخیرهٔ لایهٔ سازنده به‌علت cache حجیم webpack به کمبود دیسک رسید؛ خروجی موفق همان کانتینر (standalone، static و public) به پوشهٔ خصوصی منتقل و تصویر production از همان خروجی ساخته شد. Dockerfile مشترک اکنون cache را قبل از ذخیرهٔ لایه پاک می‌کند. ساخت کامل استاندارد بعد از افزودن cleanup تکرار نشد؛ کامپایل و ساخت تصویر اجرایی هر دو عملاً انجام شدند. پس از کمبود فضای موقت، کانتینرهای موقت همین اجرا و تصاویر بی‌نام قدیمیِ بلااستفاده پاک شدند. بانک‌ها و volumeهای برنامه حذف نشدند. لاگ‌های خصوصی ساخت در `.runtime/kp01/` هستند.

در مرورگر، مدیر پروژه PO و TL را هم‌زمان ذخیره کرد؛ پس از reload هر دو باقی ماندند و نقش فنی editor ثابت بود. تغییر مجاز از نشست دیگر، ذخیرهٔ draft قدیمی را رد کرد و پیام تعارض نشان داد؛ دریافت نسخهٔ تازه و ذخیرهٔ مجدد موفق بود. ادمین کل نیز از کلاینت نقش عضو ساختگی را تغییر داد. عضو normal فقط نقش‌ها را دید؛ checkboxها غیرفعال، دکمه‌های ذخیره و دعوت غایب بودند. ورود مستقیم او به پروژهٔ دوم اطلاعاتی نمایش نداد. جستجوی قبلی اعضا نیز کار کرد. تصویر خصوصی `roles-manager.jpg` و نتیجهٔ نمای readonly در `.runtime/kp01/` ثبت شدند. نشست ساختگی پس از آزمون logout و بسته شد؛ نشست اصلی localhost حفظ شد.

پس از آزمون، `make up` روی بانک اصلی `dify` اجرا شد. سه پروژهٔ اصلی موجودند و هیچ حساب `kp01-...@example.test` و هیچ نقش کاری خودکار در بانک اصلی نیست. `make doctor` موفق شد: تصویرهای API و وب جاری، اتصال sandbox سازگار، پورت‌های loopback، HTML فارسی/RTL با HTTP 200 و API با pong. Celery نیز به inspect ping پاسخ pong داد. در مرورگر، ورود به پروژه، کارتابل با دو اجرای قبلی، اتوماسیون موجود در وضعیت متوقف با سابقهٔ موفق، سه قالب کتابخانه و مدیریت کاربران مرکزی بارگذاری شدند. عنوان ادمین کل نمایش داده شد و بخش نقش کاری در فضای مرکزی نمایش داده نشد. نشست اصلی حفظ شد و کلاینت روی localhost:8080 روشن ماند.

## مرز پذیرش

این گام مجوز صریح اجرای ایجنت، فلو تیمی، پروندهٔ درخواست یا تصمیم PO را پیاده‌سازی نمی‌کند؛ آن‌ها گام‌های بعدند. نقش کاری، اختیار فنی یا مجوز اجرای ایجنت ایجاد نمی‌کند. تست مدل/LLM لازم نبود و اجرا نشد. RBAC خارجی Enterprise در محیط حاضر نیست و پذیرش آن ادعا نمی‌شود.
