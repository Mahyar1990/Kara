# انتقال گروه‌بندی قدیمی به پروژه‌های مستقل

این ابزار فقط برای نسخهٔ ثابت Dify ۱.۱۷.۱ و مدل قبلی گروه‌بندی بستر است. پیش از اجرا، نسخهٔ بازیابی PostgreSQL و storage محیط در مسیر خصوصی خارج از Git تهیه شود. هنگام اجرای انتقال، ساخت یا تغییر برنامه توسط کاربران متوقف باشد.

در تصویر API از `python -m company_projects.migrate_legacy` استفاده می‌شود. کنترل قبل از انتقال، اجرای فعال در برنامه‌های متصل، وابستگی مشترک دانش/اسکیل/ابزار و دارایی مادی‌شدهٔ Agent را بررسی می‌کند. مورد پشتیبانی‌نشده، قبل از انتقال برنامه‌ها خطا می‌دهد؛ انتقال وابستگی‌های پیچیده به طراحی جدا نیاز دارد.

هر پروژهٔ قدیمی یک فضای کاری بومی با مالک اولیهٔ محصول می‌گیرد. برنامه‌های متصل با همان شناسه منتقل می‌شوند و تاریخچه و رکوردهای وابسته، فضای کاری جدید می‌گیرند. اتصال مدل از پیکربندی اصلی کپی می‌شود، اعتبارنامه‌ها با کلید فضای جدید رمزنگاری می‌شوند و افزونهٔ نصب‌شده از بستهٔ موجود نصب می‌شود. مقدار توکن چاپ یا در فایل مشترک ذخیره نمی‌شود.

فضای اولیه به پروژهٔ «برنامه‌های قبلی» تبدیل می‌شود. برنامه‌های بدون پروژه و حالت اجرای آن‌ها، از جمله اجرای منتظر تأیید انسانی، در همان فضای اجرایی می‌مانند. مرکز مدیریت محصول فضای تازه و خصوصی می‌گیرد و فهرست پروژه‌ها به آن متصل می‌شود. عضویت قدیمی فضای اولیه فقط در پروژهٔ برنامه‌های قبلی باقی می‌ماند و به پروژه‌های دیگر گسترش نمی‌یابد.

ثبت داده در تراکنش بیرونی و با قفل PostgreSQL انجام می‌شود؛ commitهای داخلی سرویس اصلی داخل savepoint هستند. پیش از تأیید، مجموعهٔ شناسه‌های برنامه، فرایند، اجرا و Agent با وضعیت اولیه مقایسه می‌شود. اجرای دوباره برای فهرست کاملاً منتقل‌شده بدون تغییر است؛ حالت ترکیبیِ قدیمی و مستقل متوقف می‌شود. در شکست، بانک داده rollback و افزونه‌ها و کلیدهای فضاهای ایجادشده توسط همین تلاش جمع می‌شوند.

آزمون‌های PostgreSQL با رکورد ساختگی، حفظ شناسهٔ برنامه، باقی‌ماندن فضای اجرای قدیمی، تکرارپذیری و رد وابستگی مشترک را بررسی می‌کنند. آزمون‌ها، کاربران واقعی و داده‌های محیط را تغییر نمی‌دهند.

## بررسی انتقال محلی در ۱۰ اکتبر ۲۰۲۶

پیش از انتقال، نسخهٔ PostgreSQL و storage در مسیر خصوصی `.runtime/` تهیه شد. انتقال دو پروژهٔ موجود و ایجاد پروژهٔ «برنامه‌های قبلی» موفق بود: تعداد برنامه‌ها به ترتیب ۲، ۱ و ۶ است. شناسه‌های هر ۹ برنامه، ۷ فرایند، ۲۵ اجرا و یک Agent با وضعیت پیش از انتقال برابرند. سه اجرای paused با همان شناسهٔ فضای کاری و برنامه حفظ شدند. مرکز مدیریت تازه برنامه‌ای ندارد و حساب مالک محصول تغییر نکرد.

هر سه پروژه دقیقاً یک مالک بومی دارند. افزونهٔ مدل و یک اعتبارنامهٔ مدل در هر پروژه موجود است؛ مقدار محرمانه پس از رمزگشایی در حافظه با نسخهٔ مبدأ برابر بود و چاپ نشد. پروندهٔ مقایسه و نسخهٔ بازیابی وارد Git نشده‌اند. مجموعهٔ ۱۵ آزمون دسترسی پروژه، انتقال و اعضا نیز روی PostgreSQL موفق بود؛ این بررسی، اجرای دوبارهٔ فرایندها یا ارسال دعوت واقعی به همکاران نیست.
