# کتابخانهٔ قالب‌های پروژه

در جزئیات پروژه، «کتابخانهٔ قالب‌ها» را باز کنید. سه نمونهٔ عمومی وجود دارد: تحلیل درخواست، گزارش تیم، پاسخ از روی اسناد. مدل پیش‌فرض همان پروژه لازم است. قالب اسناد همچنین به دانش آماده و مجاز همان پروژه نیاز دارد.

«استفاده از قالب» یک برنامهٔ مستقل با نام انتخابی می‌سازد. ورودی ساختگی در فرم نمایش داده می‌شود. برنامه به‌صورت پیش‌نویس ساخته می‌شود و دسترسی وب و API آن غیرفعال است؛ تیم باید آن را آزمایش و پس از بررسی نتیجه، در ویرایشگر منتشر و در صورت نیاز دسترسی برنامه را فعال کند. هیچ برنامهٔ موجودی بازنویسی نمی‌شود. نسخهٔ قالب و شناسهٔ کامیت منبع در جدول company_template_copies ثبت می‌شوند.

قالب‌ها در workflows/starter-library شاخهٔ agents هستند. شاخهٔ master فقط امکانات کتابخانه و قفل نسخه در infra/catalog.lock.json را نگهداری می‌کند. سازندهٔ API فایل‌های همان کامیت را با Git دریافت می‌کند، فقط فایل‌های معرفی‌شده در فهرست را در پوشهٔ ساخت خصوصی قرار می‌دهد و همراه تصویر بسته‌بندی می‌کند. هنگام دریافت مخزن شرکت، تاریخچهٔ شاخهٔ agents نیز باید دریافت شود؛ اگر کامیت قفل موجود نباشد ساخت متوقف می‌شود.

مدل و دانش هنگام ساخت نسخه از همان پروژه گرفته می‌شوند؛ توکن یا سند خصوصی در فایل قالب، رابط کتابخانه یا Git قرار نمی‌گیرد. دریافت قالب داخل تراکنش بیرونی انجام می‌شود تا خطاهای دریافت یا ثبت نسخه، برنامهٔ نیمه‌ساخته باقی نگذارند. دانش خالی، پردازش‌نشده یا خارج از دسترسی کاربر رد می‌شود. این کتابخانه نمونهٔ آماده برای شروع است و به سامانه‌های بیرونی اتصال خودکار ندارد.

نسخهٔ ۱٫۰٫۱ تحلیل درخواست، مقادیر و تصمیم‌های نامشخص را به پرسش تبدیل می‌کند و معیارهای قطعی را از پیشنهادهای نیازمند تأیید جدا نگه می‌دارد. این اصلاح از آزمون واقعی قالب روی یک درخواست ساختگی گزارش هفتگی به دست آمده است؛ مدل در نسخهٔ نخست معیار عملکرد عددیِ غایب از ورودی افزوده بود. این قالب ابزار بیرونی ندارد و خروجی آن پیش‌نویس است؛ موفقیت اجرا و دقیق‌ترشدن دستورالعمل، جای تأیید کیفیت پاسخ توسط تیم را نمی‌گیرد.
