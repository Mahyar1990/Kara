# رابط فارسی و راست‌به‌چپ

رابط مشترک این پروژه با زبان `fa-IR` و جهت راست‌به‌چپ اجرا می‌شود؛ صفحهٔ نصب، ورود، منوهای مدیریتی و سازندهٔ گردش کار همین تنظیم را دارند. زبان مرورگر و ترجیح انگلیسیِ حساب قدیمی نباید رابط را انگلیسی کنند.

نسخهٔ مبنا همچنان Dify 1.17.1 است. تغییرات در [پوشهٔ رابط](../infra/web/) ثبت می‌شوند و هنگام ساخت روی یک کپی موقت از سورس اعمال می‌شوند. سورس دریافت‌شدهٔ اصلی، تنظیمات محرمانه و داده‌های محلی وارد تصویر ساخت نمی‌شوند.

## اجرای همکاران

```sh
make setup
make up
```

اولین اجرا تصویر `company-agent/dify-web:1.17.1-fa` را می‌سازد و برای دریافت وابستگی‌ها به اینترنت یا رجیستری داخلی نیاز دارد. اجرای بعدی تا زمانی که تنظیمات رابط تغییر نکرده باشد از همان تصویر استفاده می‌کند. هنگام ساخت، سرویس‌های محلی برای آزاد شدن حافظه موقتاً متوقف می‌شوند؛ داده‌ها باقی می‌مانند. در صورت خطای ساخت، سرویس‌های قبلی دوباره شروع می‌شوند.

ساخت رابط از اجرای روزمره سنگین‌تر است. برای ساخت، محیط Docker باید حدود ۸ گیگابایت حافظهٔ قابل استفاده شامل RAM و swap داشته باشد. محیط فعلی ۴ پردازنده، ۴ گیگابایت RAM و ۴ گیگابایت swap مختص ماشین مجازی پروژه دارد. پردازش ساخت محدود شده و گزینهٔ رسمی کاهش مصرف حافظه فعال است. ابزارهای ساخت داخل Docker هستند؛ نصب Node یا ابزار ساخت روی سیستم همکار ضروری نیست.

دریافت بسته‌ها با همان lockfile، مهلت ۶۰۰ ثانیه و حداکثر ۸ اتصال هم‌زمان انجام می‌شود تا timeout شبکهٔ محلی ساخت را بی‌دلیل متوقف نکند. برای ساخت، فضای آزاد دیسک میزبان و VM هر دو بررسی شوند؛ افزایش ظرفیت مجازی جای فضای آزاد میزبان را نمی‌گیرد. دیسک پروفایل فعلی به ۴۵ گیگابایت افزایش یافته است.

اگر تصویر محلیِ قابل اعتماد از مرحلهٔ کامل نصب وابستگی‌ها موجود باشد، می‌توان هنگام قطع شبکه آن را با متغیر `KARA_WEB_BUILD_CACHE_IMAGE` به `make up` داد. مقدار متغیر، شناسه یا tag همان تصویر محلی است؛ خروجی کامپایل قبلی به کار نمی‌رود. Dockerfile مشترک همچنان نصب pnpm با `--offline --frozen-lockfile` و npm با `ci --offline`، بررسی TypeScript، آزمون‌ها، کامپایل کامل و ساخت production را اجرا می‌کند. شبکهٔ مرحله‌های ساخت قطع است؛ cache ناقص یا ناسازگار باید ساخت را ناموفق کند. در حالت عادی بدون این متغیر، دریافت آنلاین انجام می‌شود. تصویر cache و store بسته‌ها وارد Git نمی‌شوند.

روی این سیستم، فایل swap در `/swapfile-company-agent-build` داخل پروفایل Colima قرار دارد و دسترسی آن 0600 است. پس از شروع مجدد ماشین مجازی، در صورت نیاز به ساخت دوباره، آن را فعال کنید:

```sh
colima ssh --profile company-agent -- sudo swapon /swapfile-company-agent-build
```

این فرمان مخصوص محیط فعلی و فایل آماده‌شدهٔ آن است. همکارانی که Docker حافظهٔ کافی دارد به آن نیاز ندارند. اجرای روزمرهٔ سرویس‌ها به ساخت مجدد رابط نیاز ندارد.

در ساخت مشترک، پس از موفقیت Next.js پوشهٔ `.next/cache` از لایهٔ سازنده پاک می‌شود. این پوشه فقط cache کامپایل است و در خروجی اجرایی standalone کاربرد ندارد؛ نگه‌داشتن آن می‌تواند هنگام ذخیرهٔ لایهٔ Docker دیسک محدود VM را پر کند. خروجی‌های standalone، static، public و مجوز فونت حفظ می‌شوند.

## نگهداری ترجمه

- [ترجمه‌های تکمیلی](../infra/web/fa-overrides.json): تکمیل ترجمهٔ فارسی موجود، به‌ویژه منوهای جدید.
- [متن‌های ثابت رابط](../infra/web/literal-translations.json): برچسب‌هایی که در نسخهٔ مبنا خارج از سامانهٔ ترجمه نوشته شده‌اند؛ ابزار ساخت آن‌ها را در ساختار JSX تبدیل می‌کند.
- [تغییرات سورس](../infra/web/source.patch): زبان ثابت فارسی، جهت سند، رفتار راست‌به‌چپ کنترل‌ها و اتصال پردازشگر CSS.
- [چیدمان و فونت](../infra/web/persian.css): فونت محلی وزیرمتن و جهت بخش‌های فنی.
- [مقادیر فنی](../infra/web/technical-values.json): نام سرویس‌ها، قالب تاریخ، نمونهٔ نشانی و شناسه‌های قراردادی که باید مقدار اصلی خود را حفظ کنند.

نام نمایشی محصول Kara است: عنوان پیش‌فرض، نشان نوشتاری، favicon، ناوبری، ورود، راه‌اندازی و متن‌های داخلی مربوط به استفاده از محصول. تنظیم branding اختصاصیِ فعال همچنان بر پیش‌فرض عنوان/لوگو مقدم است. [patch نام محصول](../infra/web/branding.patch) و overlayها این رفتار را بدون تغییر سورس upstream اعمال می‌کنند. عنوان صفحه‌های اختصاصی پسوند تکراری ندارند و از الگوی سراسری عنوان استفاده می‌کنند.

برچسب و توضیح فارسی است؛ کد، ایمیل، نشانی، کلید فنی و نام سرویس‌هایی مانند GitHub شکل فنی خود را دارند. نام Dify در ارجاع به نسخهٔ مبنا، مجوز، بازار و سرویس بیرونیِ آن باقی می‌ماند. متون واردشده توسط کاربر، پاسخ مدل، محتوای افزونه‌ها یا بازار بیرونی و پیام‌های خطایی که سرویس‌ها به‌صورت متن ارسال می‌کنند، ترجمهٔ خودکار نمی‌شوند. اگر افزونه‌ای متن رابط اختصاصی انگلیسی داشته باشد، برای آن ترجمهٔ اختصاصی لازم است.

فونت و دارایی‌های Kara از داخل سرویس ارائه می‌شوند و دریافت آن‌ها از سرویس عمومی در مرورگر لازم نیست. مجوز فونت، مجوز upstream و انتساب LangGenius حفظ می‌شوند؛ نشان محصول در صفحه‌های اصلی Kara است.

## بررسی

ساخت، کامل بودن کلیدهای فارسی و حفظ متغیرهای داخل متن را بررسی می‌کند؛ متن ثابت انگلیسی جدیدِ خارج از فهرست مقادیر فنی، ساخت را متوقف می‌کند. آزمون‌های CSS فاصله‌ها، جهت محلی قسمت‌های فنی و انتخابگرهای شبه‌عنصر را بررسی می‌کنند.

```sh
make check
make doctor
```

بررسی ظاهری تکمیلی: صفحهٔ نصب و ورود، منوی حساب، تنظیم مدل، پنجره‌های انتخاب، پیمایش با صفحه‌کلید، فرم فارسی، کد و ایمیل، و جابه‌جایی گره‌های گردش کار. بررسی ظاهری صفحات پس از ورود به حساب فعال نیاز دارد؛ نتایج آزمون سورس و HTTP به‌تنهایی جای آن را نمی‌گیرند.

مراجع پیاده‌سازی: [جهت کنترل‌های Base UI](https://base-ui.com/react/utils/direction-provider) و [پردازش CSS با PostCSS RTLCSS](https://github.com/elchininet/postcss-rtlcss).
