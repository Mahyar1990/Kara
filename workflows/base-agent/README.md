# قالب پایهٔ ایجنت

نسخهٔ ۰٫۱؛ Dify 1.17.1. این قالب مستقل از محصول، نوع درخواست و ابزار مدیریت کار است. نام پروژه، نام و نقش ایجنت، هدف، دستورالعمل اختصاصی و ساختار متن نتیجه قابل تنظیم‌اند. متن کار، مرجع اختیاری، منابع دارای متن و نسخهٔ کار، ورودی اجرای آن هستند.

[ارزیابی محیط محلی](../../docs/base-agent-evaluation-2026-10-09.md): قالب وارد شده و ۵۱ آزمون محلی موفق‌اند؛ اجرای کامل دو نقش به‌علت قطع اتصال مدل هنوز تأیید نشده است.

مسیر: تعریف پروژه و ایجنت ← ثبت نسخه و شناسه ← اجرای مدل ← کنترل خروجی ← نتیجهٔ آزمایشی. این نسخه برای تهیهٔ متن و آزمایش نقش است؛ ابزار بیرونی، دسترسی فایل، اتصال ایجنت‌ها و ثبت تصمیم انسانی ندارد. اضافه‌کردن نام یک ابزار در دستورالعمل، آن ابزار را متصل نمی‌کند.

## استفاده در Dify

۱. در استودیو، فایل [workflow.yml](workflow.yml) را از گزینهٔ ورود DSL وارد کنید یا از برنامهٔ «قالب پایهٔ ایجنت» یک نسخهٔ کپی‌شده بسازید و نام مناسب بدهید.

۲. در گره «اجرای آزمایشی ایجنت»، مدل ثبت‌شدهٔ محیط خود را انتخاب کنید. قالب مشترک نام مدل یا توکن محیط را ندارد. چک‌لیست فرایند باید بدون مشکل باشد.

۳. در گره «تعریف پروژه، ایجنت و کار»، پیش‌فرض فیلدهای پروژه، نام، نقش، هدف، دستورالعمل و ساختار نتیجه را برای ایجنت خود تنظیم کنید. فیلدهای کار و زمینه را برای هر اجرا پر کنید. این نسخه فقط نام پروژه را ثبت می‌کند؛ مخزن و مستندات به‌صورت خودکار خوانده نمی‌شوند. منابع دارای متن باید صریح وارد شوند.

۴. «اجرا» را بزنید؛ تنظیمات و متن کار را بررسی و «شروع اجرا» را انتخاب کنید. ورودی اجباریِ خالی پیش از مدل رد می‌شود.

۵. در «نتیجه»، report، result_status و run_record_json را ببینید. completed به معنی پایان تهیهٔ متن این مرحله است؛ نیاز به اطلاعات با needs_input و سؤال‌های مشخص ثبت می‌شود. پاسخ نامعتبر invalid_output می‌شود. همهٔ خروجی‌ها آزمایشی و تصمیم انسانی بررسی‌نشده‌اند.

۶. با تغییر نقش و ساختار نتیجه، همان قالب را برای کار دیگری آزمایش کنید. نمونه‌های [تحلیل درخواست](../../fixtures/base-agent/requirement.json) و [ویرایش متن](../../fixtures/base-agent/editor.json) همگی ساختگی‌اند. آن‌ها دادهٔ واقعی محصول یا سیاست سازمان نیستند.

## ثبت نسخه و قرارداد خروجی

تنظیمات پروژه و ایجنت از متن کار جدا هستند. شناسهٔ تنظیمات از محتوا و نسخهٔ قالب ساخته می‌شود؛ تغییر پروژه، نقش، هدف، دستورالعمل یا شکل نتیجه آن را تغییر می‌دهد. شناسهٔ کار علاوه بر آن به متن، زمینه، مرجع و شمارهٔ نسخهٔ کار وابسته است. این شناسه‌ها حساب کاربری، شناسهٔ جیرا یا مجوز نیستند.

مدل دقیقاً status، result و questions را برمی‌گرداند. کنترل قالب، ساختار پاسخ را بررسی می‌کند و رکورد اجرای مستقل می‌سازد؛ متن مدل نمی‌تواند can_execute_tools، can_handoff یا can_merge را فعال کند. صحت معنای نتیجه همچنان نیازمند بازبینی انسان است. داده‌های اجرای شخصی در Dify و پروندهٔ خصوصی محیط می‌مانند؛ وارد Git نشوند.

## بازسازی و بررسی قالب

```sh
python3 scripts/build_base_agent.py
python3 scripts/build_base_agent.py --check
```

برای ساخت نسخهٔ خصوصی با نام مدل ثبت‌شده در محیط:

```sh
python3 scripts/build_base_agent.py --local --model AIFA-Sand
```

فایل خصوصی داخل `.runtime/workflows/base-agent.local.yml` با دسترسی ۶۰۰ ساخته می‌شود و از Git کنار گذاشته شده است. ورود فایل به Dify به‌تنهایی اتصال درست مدل را ثابت نمی‌کند؛ انتخاب مدل و اجرای واقعی لازم است. این قالب فقط یک برنامهٔ جدید می‌سازد و فرایندهای موجود را تغییر نمی‌دهد.

در نسخهٔ مشترک فقط دستورالعمل، منطق ثبت نسخه، قرارداد خروجی و قالب فرایند نگهداری می‌شود. افزودن ابزار، نقش سازمانی، اجراکننده و شروع خودکار، قابلیت‌های مراحل بعد هستند.
